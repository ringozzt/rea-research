01 — EXECUTIVE VERDICT

先去掉名字制造的幻觉

PRIMARYREA 的官方定义是：“一个用于二进制、应用与运行时行为逆向工程的 MCP。”它给 Claude Code、Cursor、Codex 等 agent 一套统一工具，让 agent 在没有源代码时检查、解释，并基于证据帮助重建功能。[P1]

它改变的是逆向工程的交互层：从专家操作 GUI，变成 agent 围绕证据循环。底层反编译能力仍然来自成熟引擎。

所以，“能逆向工程”是真的；“输入一个 App，自动吐出原始源码”是错的。REA 官方明确不承诺恢复原始源代码，也不承诺整包克隆。它返回伪代码、汇编、模块关系和运行时观测，由 agent 再写实现。[P1]

真正的新东西

跨工具统一抽象、可追溯 evidence bundle、limitations / unknowns、版本比较，以及把“找功能 → 下钻 → 验证”产品化。

不是它发明的

反编译、反汇编、APK 解包、固件提取、浏览器网络观测。REA 调用现有 provider，不替代它们。

decompile → trace → recreate

03

重建并验证

Agent 在用户自己的项目里写实现，再用行为测试、字节比较或版本 diff 回证。

四层结构：REA 占的是中间两层

CODING AGENT
Claude Code / Codex / Cursor / Gemini CLI 等，负责提问、推理、写代码。
REA WORKFLOW
工作流产品化： guided prompts、setup / doctor、snapshot 复用、跨层追踪。
EVIDENCE CONTRACT
结果形状： result + evidence_id + provenance + confidence + limitations + unknowns。
PROVIDERS
Hopper / Ghidra / IDA / JADX / Binwalk / Unblob / pwntools / CDP / mitmproxy / ADB / JEB / LLDB…
TARGETS
Native、Electron、.NET、APK、firmware、website、HAR、EVM、crash、process behavior。

PRIMARY原生 provider 可在 Hopper、Ghidra、IDA 间切换；REA “rides an existing install”。Ghidra 走打包的 headless script 与隔离临时项目；IDA 基于开源 ida-pro-mcp，并核对原始二进制 SHA-256，避免 agent 静默分析错数据库。[P4]

证据合同为什么比“工具数量”更关键？ 普通 MCP wrapper 把 GUI 操作暴露成按钮；REA 试图让每个结论都可引用、可导出、可比较，并主动保留 unknowns。它甚至声明不会伪造进度百分比；文件 hash 与字节矛盾时默认 fail-closed。后两项来自二手技术拆解，方向与官方“evidence + limitations”一致。[S2]
03 — COVERAGE

“Anything” 是路线图，不是现状

Native binaries

伪代码、汇编、字符串、符号、调用与引用；Hopper / Ghidra / IDA 三选一。

JS / Electron

模块、导入、source map、路由、IPC、ASAR 与原生 addon；静态分析可不运行应用。

Android / firmware

JADX、ADB、JEB、Apktool；固件经 Binwalk / Unblob 切分后转交原生分析。

Web / runtime

CDP、页面结构、脚本、截图、HAR、mitmproxy、进程输出与文件系统观测。

.NET / EVM / ELF

CIL 与元数据、EVMole 字节码、pwntools 离线 ELF layout 与 recorded crash。

仍然难

混淆、加壳、反调试、动态生成行为、冷门架构，以及永远不下发到客户端的服务端逻辑。

PRIMARY目标矩阵与 provider 来自 README / release notes。Windows 原生支持仍窄于 Linux/macOS，部分路径标为 experimental Ghidra-only P0。[P2]

05 — SHOWCASES

案例证明了什么，也没证明什么

DX-Ball：最强的一条证据链

NATIVE / X86 / 1996

反编译器初看只给出 FUN_00406400(void) 与 __ftol()。Agent 下钻指令发现参数在 [EBP+8]，沿调用者得到输入语义 20 + 30 × tile_x，再从字节中解出 1.5625 与 500.0。

pan = ((double)x * 1.5625 - 500.0) * dxball_pan_scale
3,205行为测试全部匹配
63 / 63重编译函数字节一致
33 / 55已维护函数达字节匹配

PRIMARY这证明“反编译缺口 → 指令补全 → 常量读取 → C 重写 → 行为与字节双验证”闭环可行。它没有证明整程序自动克隆：目标未混淆、函数粒度明确、还复刻了 VC4.0 工具链。[P6]

Notion：跨 Electron 进程边界

ELECTRON / IPC / ASAR

REA 沿 clipboard.write → preload 的 invokerInMain → ipcRenderer.invoke → 主进程 ipcMain.handle 追踪复制链路。它还发现复制 HTML 中的 <!-- notionvc: <copy-id> -->，用于找回本地结构化 block 数据。

PRIMARY它证明统一工具可以跨 renderer / preload / main / SQLite utility process 追踪；但官网明确说展示代码经过简化，probe 描述的是受控测试，不是真实桌面会话的完整证明。[P7]

“Vault test”：只能算演示

THIRD-PARTY DEMO

SECONDARY第三方视频自述这是演示者自己的 demo，屏幕上的函数地址和汇编为简化示意。它不能承担“真实闭源应用已被完整还原”的证明责任。[S7]

独立复现的真实上限SECONDARYkingy.ai 用 REA 6.0.0 重建 Notes 的 CSV 导出，14 个测试全部通过；但作者明确说，这“不证明对不透明二进制的准确性，也不证明完整 App 克隆”。同次实验里，1,648B 源码产生约 907KB JSON evidence，显示证据输出很重。[S4]
06 — TRUST & SECURITY

本地分析，不等于全程私密

它保护了什么

  • 目标二进制在本机分析，不上传 REA 托管服务。
  • Provider bridge 用随机 capability token 与当前用户 Unix socket 认证。
  • Ghidra 用隔离临时项目与私有 home/cache/runtime 目录。
  • IDA 核对 SHA-256，避免静默分析错误数据库。

它没保护什么

  • 不是恶意样本沙箱。
  • Provider 仍以当前 OS 用户权限解析目标。
  • 工具结果会交给 agent，再受模型供应商数据政策约束。
  • Runtime capture 可能直接运行目标。
SECURITY.md 原文：
“This is not a sandbox.”[P3]

对企业最关键的合规问题不是“二进制有没有上传 REA”，而是反编译结果会不会被云模型看见。处理专有代码时，需要匹配模型供应商的数据政策；处理不可信目标时，应优先隔离 VM、本地模型，或只做静态分析。

容易踩的工程坑

  • Node：支持 22.x（≥22.19）、24.x（≥24.11）、26+；不支持 23、25、预发布版。REA 不替你升级 Node/npm/Homebrew。[P4]
  • Provider：原生二进制必须自备 Hopper / Ghidra / IDA 之一；APK 需 JDK + JADX；firmware 需 Linux 与 Binwalk/Unblob。
  • 超时：二手实测提到 Ghidra 首次查询可到 330 秒，而某些 MCP client 默认只有 60 秒。[S3]
  • 输出：“150MB App → 577MB JSON”只有视频口径，未获文本证实；可以确认的只有 1,648B → 约 907KB 的独立实验。
07 — LIMITS & LAW

技术边界之外，还有授权边界

美国

BACKGROUNDDMCA §1201(f) 为实现独立程序互操作性提供有限规避例外；Sega v. Accolade、Sony v. Connectix 支持特定合理目的下的中间复制。但许可条款与 CFAA 风险仍取决于具体事实。

欧盟

BACKGROUND2009/24/EC 第 6 条仅在实现互操作所必需时允许反编译：合法用户、信息不易获得、限于必要部分、不得开发“表达上实质相似”的程序。

中国

OPEN QUESTION本次未深挖一手法源。通识上受著作权、商业秘密、技术措施与许可合同共同约束；不能把“学习研究通常被容忍”当成普遍免责。

REA 的立场

PRIMARY只支持合法研究、分析与重建；用户负责取得授权并遵守法律。项目还明确没有发行或背书任何 REA 加密货币 / token。[P1]

为什么双重用途争议在这个时间点爆炸

SECONDARY2026 年 10 月初，媒体报道攻击者用中国开源 agent Artex AI 攻击至少 7 家韩国金融机构，约 68,000 人信息泄露；REA 5.0.0 恰在 10 月 7 日发布，次日登顶 trending。两者没有直接关联，但共享同一个叙事：agent + 开源工具正在压低攻防门槛。[S11]

不是法律意见逆向是否合法高度依赖目标、授权、许可条款、用途、复制范围与法域。最稳妥的安全区仍是：自己的软件、开源二进制、CTF、或明确获授权的目标。

REA v5 的 133 tools 甚至少于 ghidra-mcp v6 的 272。数字不能说明平台能力。REA 的差异是：同一个 agent 能从 Electron renderer 追到 main，再追到 native addon，而不必在多个工具与上下文之间人工搬运证据。

最准确的类比如果 Ghidra/IDA 是数据库引擎，REA 更像查询规划器 + provenance 层 + 开发者工作流。它依赖底座，却能用跨底座的连续上下文创造新价值。
09 — IMPLICATIONS

“旧的保护是成本”

过去，逆向的防线之一是专家小时：即使逻辑随客户端交付，定位、理解、验证也足够贵。REA 把这条链压缩成 agent 可执行的循环。它没有让逆向变成零成本，但让更多人有能力开始。

软件厂商还剩下什么防线

技术防线

混淆、加壳、反分析、动态行为、冷门架构。它们不是绝对保护，却继续抬高验证成本。

架构防线

服务端逻辑与数据不随客户端发货。SaaS 的护城河不在本地二进制里。

法律防线

版权、商业秘密、技术措施与 license 条款，仍能把“能做”与“可合法商业化”分开。

商业防线

网络效应、品牌、分发、持续交付与执行速度。复制一个函数，不等于复制一个业务。

五条硬发现

它是“反编译器的 agent 化编排层”

核心不是新算法，而是统一 provider、证据合同和跨层追踪。

3,205 / 63 是单函数闭环，不是整 App 克隆

最强 showcase 同时也是边界声明。

“This is not a sandbox” 是官方白纸黑字

本地运行与安全隔离是两回事；本地分析与模型隐私也是两回事。

79k stars 与约 1.3k npm 周下载形成巨大温差

热度属实，真实采用仍待观察；二者口径与时间点不同，只能定性比较。

它把闭源客户端的壁垒从“看不懂”推向“藏不住”

壁垒会进一步迁往服务端、数据、网络效应与迭代速度。

10 — ECOSYSTEM

采用路径已经很产品化

# 推荐：给已检测到的 coding agent 配置 REA
npx rea-agents setup

# 全局 CLI
npm install --global rea-agents
rea doctor

# 零配置分析 JS / Electron
npx -y rea-agents@latest analyze-javascript-application /absolute/path --json

PRIMARY官方列出 14 个 agent 客户端，包括 Claude Code、Claude Desktop、Codex、Cursor、Gemini CLI、Windsurf、Devin、OpenCode、GitHub Copilot CLI、VS Code 等。rea doctor 可以审计客户端注册、skill 与 provider；setup 会先展示计划、备份配置、原子写入，安装 Hopper 还需单独批准。[P4]

采用建议如果只是 Electron / JS 静态分析，可以从零配置 CLI 开始；如果分析 native，先选定并跑通一个 provider，再接 agent。不要一上来追求“133 个工具全装齐”。
